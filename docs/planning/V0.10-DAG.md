## 2. 并行批次与关键路径

```
P0  Lead：本 DAG + 任务板 + 接口冻结
P1  A-ir   B-resolve   C-manifest   D-secret   E-templates        （5 并行）
P2  F-local   G-github                                            （2 并行，等 A）
P3  H-apply   I-tools   J-client                                  （3 并行，等 A–G）
P4  K-rename                                                      （1，等 A–J）
P5  L-smoke   M-clienttest                                        （2 并行，等 K）
P6  N-verify + Lead 终审                                           （等 L,M）
```

关键路径：**A → F/G → H/I/J → K → L/M → N**。
P1 中只有 A 被下游依赖，B/C/D/E 是「纯新增或孤立改造」，可完全并行。

## 3. 冻结接口（跨模块契约，必须逐字满足）

### 3.1 `lib/pipeline/ir.js`（A）

保留导出：`STAGE_CATALOG`、`STAGE_IDS`、`JOB_ORDER`、`DEFAULT_STAGE_IDS`、`runOf`、`legacyStageIds`、`parseStageList`、`resolveStages`、`groupJobs`、`stageMatrix`。

新增导出：`COMMIT_STAGE_IDS = ['lock','lint','manifest']`；`OPTIONAL_STAGE_IDS = ['integration','audit','container','release','deploy']`。

`STAGE_IDS` 新顺序（13 个）：

```js
['lock','sync','lint','type','manifest','test','security','build',
 'integration','audit','container','release','deploy']
```

前 8 个为默认（`optional !== true`），后 5 个 `optional: true`。阶段命令：

| 阶段 | steps（argv，全部 `kind:'run'`） |
|---|---|
| `lock` | `['uv','lock','--check']` |
| `sync` | `['uv','sync','--locked','--all-groups']` |
| `lint` | `['uv','run','--locked','ruff','check','.']`、`['uv','run','--locked','ruff','format','--check','.']` |
| `type` | `['uv','run','--locked','mypy', ...类型路径]`（默认 `['src']`；路径与 checker 由 resolve 注入，阶段里写占位注释，渲染时替换） |
| `manifest` | `['uv','run','--locked','python','scripts/validate_version_manifest.py']` |
| `test` | `['uv','run','--locked','pytest','--cov','--cov-report=term-missing']`（门槛读 pyproject，不在命令行写死） |
| `security` | `['uv','run','--locked','python','scripts/secret_scan.py']` |
| `build` | ①`['uv','run','python','-c','import shutil,sys; shutil.rmtree(sys.argv[1], ignore_errors=True)','dist']`（id `clean-dist`）②`['uv','build','--all-packages','--out-dir','dist']` |

- `container`：compose-config / compose-build-check / compose-build / compose-up / compose-ps / compose-identity / **container-report**（`['uv','run','python','scripts/container_report.py']`，只报告，size limit 配置了才非零）/ compose-down（`always: true`）；`compose-down-volumes` 保持 `commented: true`。
- `release`：**删除 `release-build`**；`release-download` = `uses: actions/download-artifact@v4`, `with {name:'dist', path:'dist'}`；attest / sbom / upload（`name: dist-release`）/ tagged publish 与镜像 / `gh release create` 保持，全部依赖同一份 `dist`。
- `deploy`：`deploy-run` 改为**真实失败步骤**（`runs: ['echo "::error::部署命令未配置：把本步替换成你的部署命令"', 'exit 1']`，`verified:false`、`local:false`，不再 `commented`）；`deploy-smoke` 加 `if: "vars.DEPLOY_HEALTH_URL != ''"`；`deploy-verify` 保持 `local:false`。
- `type` 的 checker 与路径：阶段对象带 `resolver: 'type'` 标记（新字段，渲染器据此向 resolve 取值）；`build` 带 `resolver: 'build'`，`test` 带 `resolver: 'coverage'`，`manifest`/`security` 的脚本路径固定。
- `stageMatrix()` 每行新增 `defaultIncluded`（已有）、`optional`（布尔）、`kind: 'gate' | 'delivery'`。

### 3.2 `lib/detect.js` + `lib/resolve.js`（B）

`lib/detect.js` 保留现有全部导出，新增：

```js
export function readPyprojectTables(rootDir) // → { path, exists, text, tables: {}, error? }（宽松解析，失败不抛）
```

`detect()` 返回值新增字段（不得删旧字段）：

```js
{
  workspace: { isWorkspace, members: [], sources: [] },
  buildBackend: 'uv_build' | 'hatchling' | 'setuptools' | null,
  mypy: { configured: Boolean, hasConfigTable: Boolean },
  secrets: { baseline: Boolean, helper: Boolean },
  validator: { script: Boolean, manifest: Boolean },
  container: { reportScript: Boolean, imageLimit: Number|null },
  gitHooks: { installed: Boolean, pointsToPrek: Boolean }
}
```

`lib/resolve.js`：

```js
export function resolveProject({ rootDir, detection }) // → 见下
export function describeResolved(resolved) // → string[]，如 'ruff.line-length=88 (default)'
```

`resolveProject` 返回扁平对象，每个键 `{ value, source }`，`source ∈ {'existing','detected','default'}`：

```
pythonVersion, requiresPython, testPaths, coverageFloor (number|null),
ruffLineLength (number), ruffSelect (string[]), ruffIgnore (string[]),
typeChecker ('mypy'|'ty'), typePaths (string[]),
buildMode ('all-packages'|'package'), workspaceMembers (string[]),
manifestComponents ([{id, path?, sha256?, version?}]), manifestPath, validatorPath,
secretBaseline, secretHelperPath, containerReportPath, imageMaxSizeMb (number|null)
```

取值规则见计划 §5：`existing > detected > default`；不得静默用默认（每条必须能在 `describeResolved` 里看到 source）。

### 3.3 `lib/manifest.js`（C）

```js
export const MANIFEST_PATH = 'release/agent_versions.json'
export const VALIDATOR_PATH = 'scripts/validate_version_manifest.py'
export const COMPONENT_IDS = ['prompt','chat_model','skills','tools','harness','embedding','knowledge_base','index','evaluation']
export function probeComponents({ rootDir, detection })      // 只返回项目真实存在的组件；不得伪造 path
export function renderManifest({ projectName, version, pythonVersion, uvVersion, lockfile, components }) // → object
export function renderValidator({ components })              // → 仅标准库 Python 源文本
export function diffManifest(existing, next)                 // → { changed: Boolean, lines: string[] }
```

校验器行为对齐计划 §6：JSON 解析、顶层四字段、九组件、path+sha256 成对、`is_relative_to` 防越界、`is_file`、sha256 比对；失败打印中文原因并 `return 1`；成功打印服务名与版本。
校验器内生成 `PROJECT_COMPONENTS = [...]` 常量（本项目的真实组件），只校验清单里出现的组件。
`release/agent_versions.json` 生成规则：已有文件 → 不覆盖，输出 diff 提示人工审核；`service.version` 取 pyproject 版本；组件初始 version `<name>-1.0.0`。

### 3.4 `lib/secret-scan.js`（D）

```js
export const SECRET_HELPER_PATH = 'scripts/secret_scan.py'
export const BASELINE_PATH = '.secrets.baseline'
export function renderSecretScanScript() // → 仅标准库 Python 源文本
```

生成脚本 CLI：`python scripts/secret_scan.py [--staged] [--baseline PATH] [--root PATH]`。

- 取文件：默认 `git ls-files -z`；`--staged` 用 `git diff --staged --name-only --diff-filter=ACM -z`；decode 后排除 `.secrets.baseline`。
- 调用 `uv run --locked detect-secrets-hook --baseline <baseline> <files...>`，透传退出码。
- **缺 baseline**：打印 `No such file or directory: .secrets.baseline` + 三行指引（scan → audit → 再跑），退出 1。
- **detect-secrets 未安装**：打印 `detect-secrets is not recognized: 请先 uv sync --locked --all-groups`，退出 2。
- 这两个英文标记是给 `py-pipeline-run` 的 `failureKind()` 归类用的，**不得改写措辞**。

### 3.5 `lib/pyproject.js` + `lib/prek.js`（E）

`renderPyprojectBlock(opts)` 保持旧参数兼容，新增可选：`{ typeChecker, ruffLineLength, ruffSelect, ruffIgnore, coverageFloor, includeWorkspace, workspaceMembers }`。
默认值严格照第八章：`line-length=88`、`select=["E","F","I","B","UP"]`、`[tool.mypy] strict=true` + `python_version`、`addopts="-ra --strict-markers"`、`testpaths`、`[tool.coverage.run] branch=true` + `source=[...]`、`[tool.coverage.report] show_missing=true` + `fail_under=<resolve 值>`、四依赖组 `lint/test/security/dev`、`[tool.uv] required-version`、workspace 时 `[tool.uv.workspace] members` 与 `[tool.uv.sources]`。
`typeChecker==='ty'` 时才渲染 `[tool.ty.*]`。

`renderPreCommitConfig({ pythonVersion, includeBuiltin = true, includeSecurity = false })`：
- 删除 `Yelp/detect-secrets` 远程钩子；
- 新增 `repo: local` 两个钩子：`gatekeeper`（`entry: uv run --locked python scripts/ci.py --profile commit`，`language: system`，`pass_filenames: false`，`always_run: true`）与 `gatekeeper-secrets`（`entry: uv run --locked python scripts/secret_scan.py --staged`，`language: system`，`pass_filenames: false`，`always_run: true`）；
- `prekNextSteps()` 返回：`uv tool install prek`、`prek install`、`prek run --all-files`，并提示首次需要创建/审核 `.secrets.baseline`（scan + audit，禁止 `scan >` 覆盖）。

### 3.6 `lib/pipeline/local.js`（F）

```js
export function localPlan(ids, { timeoutSeconds = 900, profile = 'full' })
export function renderCiScript(plan, { projectName, profile = 'full' })
```

`scripts/ci.py` 生成的 CLI 必须支持：`--stage`（默认 `all`）、`--profile full|commit`、`--from <stage>`、`--list`（**按 job 分组**，组头 `[job quality]` 等）、`--root`、`--timeout`、`--stop-after`、`--json`。
运行时打印到每个 job 组：`[job container] 需要 docker daemon` 这类一句提示（从 stage 的 `job`/`why` 生成，不写死）。

### 3.7 `lib/pipeline/github.js`（G）

`renderWorkflow(options)` 签名不变。行为：
- 有 `sync` 阶段 → 渲染 `- name: Install dependencies` / `run: uv sync --locked --all-groups`（替换现在写死的第 343-344 行逻辑）；
- `needsUv` 按 job 内是否存在 `uv ` 命令计算（release job 改完后**不再装 uv**；checkout 保留，`gh` 需要仓库上下文）；
- step 有 `always: true` → 渲染 `if: always()`；
- `deploy-smoke` 的 `if` 原样渲染；
- `runs` 数组 → `run: |` 多行；
- 有 `build` 阶段 → `upload-artifact@v4`（`name: dist`、`path: dist/`、`if-no-files-found: error`）；
- `lock` 阶段渲染在 `Install dependencies` **之前**；
- 其余 job 结构（`quality`/`container`/`release`/`deploy`、`needs`、`permissions`、`environment`、`concurrency`、`timeout-minutes`）保持不变。

## 4. 通用规则（每个节点都适用）

1. **只用 wsl 工具执行 shell**（pwsh 在本机坏了：`0xC0000142`）。Node 路径：`'/mnt/c/Program Files/nodejs/node.exe'`。项目目录：`/mnt/e/dsh-plugin-creator/python-toolchain`。
2. 自检方式：`cd /mnt/e/dsh-plugin-creator/python-toolchain && '/mnt/c/Program Files/nodejs/node.exe' -e "import('./lib/xxx.js').then(m=>console.log(Object.keys(m)))"`。**不要**指望 `node test/smoke.mjs` 中途是绿的（L 节点统一重写断言）。
3. 只写自己的范围。需要改别人文件 → 在报告里写「阻塞：需要 X 的 Y」并停手，不要跨界。
4. 不碰 `V0.6-PLAN.md`、`V0.10-PLAN.md`、`V0.10-DAG.md`、`README*`（K/N 阶段处理）。
5. 不新增第三方依赖；Node 只用标准库；生成的 Python 只用标准库。
6. 每个节点结束时回报：改了哪些文件 / 新增导出 / 与契约的偏差 / 自检命令与输出尾部 / 阻塞项。
7. 注释保留现有风格：解释「为什么」，不写「做了什么」。
