# python-toolchain v0.6 · CI/CD 全链路方案

> 定稿日期：2026-10-21 · 基线版本 0.5.4 · 目标版本 0.6.0
> 六轮 grill 收敛结果。本文件是实施依据，不是宣传材料。

## 1. 决策记录（已确认）

| 项 | 结论 | 理由摘要 |
|---|---|---|
| 边界 | 生成配置 + 审计现有仓 + 本地一键跑 | 三者共用一套 stage 模型 |
| 执行体 | 纯 Python `scripts/ci.py`，标准库 only | Windows 与 ubuntu 同一条命令 |
| 范围 | 只生成 GitHub Actions、只面向 Python；中间加 `ir → renderer` 接缝 | 加平台只新增渲染器 |
| 阶段 | (a) container 纳入 v0.6；release 半开；deploy 只给清单 | 不可验证的模板必然腐烂 |
| 审计深度 | 静态 + 白名单命令本地试跑 | 能发现「YAML 合法但命令写错」 |
| 输出 | 默认只读；`--apply` 才写，写前备份 | 沿用「不自动写你的文件」承诺 |
| 工具命名 | 保留 `py-ci-plan` / `py-ci-render`，扩展参数 | 工具名是公开契约 |
| 版本 | 一个 0.6.0 全出 | ir 层只重构一次 |

**判定规则（贯穿全版本）**：任何 stage 能进版本，条件是本地 runner 能跑出 pass/fail；跑不出的，只做门禁与清单，不生成 YAML。

## 3. 新增模块

```
lib/pipeline/ir.js        stage 目录与步骤对象（唯一事实来源）
lib/pipeline/local.js     本地命令序列 + scripts/ci.py 源码生成
lib/pipeline/github.js    IR → workflow YAML（唯一渲染器）
lib/pipeline/audit.js     静态审计规则
lib/pipeline/exec.js      白名单执行器
lib/tools/py-pipeline-doctor.js   审计工具
lib/tools/py-container-gate.js    container job 生成 + 本地验
lib/tools/py-ci-run.js            本地跑 stage
lib/templates/ci.py         scripts/ci.py 模板（stdlib only）
```

改造：`py-ci-render` 增加 `stages` / `emitScript` / `includeRelease`；`lib/schema.js` 增 3 个工具开关；`index.js` 注册 3 个新工具；`/python-toolchain/status` 增加 `stages` 字段。

### IR 形状

```js
{ id: 'lint', title: '静态检查', why: '…', needs: [],
  steps: [ { id:'ruff-lint', kind:'run', argv:['uv','run','--locked','ruff','check','--output-format=github','.'], verified:true, replaces:['py-ci-plan#lint'] } ] }
```
- `kind: 'run' | 'uses'`
- `verified: false` 的步骤在 YAML 里加 `# 未在本地验证` 注释，且在 `all` 里不默认启用
- `needs` 决定 job 依赖（容器 job `needs: quality-gate`）

## 4. Doctor 规则（静态，共 13 条）

| id | 级别 | 判据 |
|---|---|---|
| `pin-policy-mixed` | warn | 同一文件里既有 SHA 钉死又有浮动大版本 |
| `job-timeout-missing` | warn | job 无 `timeout-minutes` |
| `no-artifact` | error | 无 `upload-artifact` |
| `artifact-always-error` | warn | `if: always()` 且 `if-no-files-found: error` |
| `sync-unlocked` | error | `uv sync` 缺 `--locked` |
| `run-unlocked` | warn | `uv run` 缺 `--locked` |
| `pip-install` | error | CI 内出现 `pip install` |
| `no-concurrency` | warn | 无 `concurrency` 组 |
| `permissions-missing` | warn | 无 `permissions:` |
| `coverage-floor-missing` | warn | 无 `--cov-fail-under` 且 pyproject 无 `fail_under` |
| `uv-version-drift` | info | workflow 声明的 uv 版本与本地 `uv --version` 不一致 |
| `container-stage-missing` | info | 有 Dockerfile/compose 但无容器 job |
| `secret-in-run` | error | `run` 里出现明文口令模式 |

规则只做静态解析，**不联网**（不校验 action 标签是否存在，避免误报；`checkout@v7` 等在 2026 年真实存在）。

### 白名单执行
只有这些 argv 前缀允许执行，其余一律拒绝并列明原因：
`uv sync` / `uv run` / `uv build` / `uv lock --check` / `docker compose config` / `docker compose ps` / `docker build --check`
默认 `run: false`，必须显式传参才执行。

### 已在靶子上发现的真实问题（v0.6 必须能报出来）

1. `ci.yml` 里 `checkout@v7` / `setup-python@v7` / `upload-artifact@v7` 用浮动大版本，而 `setup-uv` 钉到 commit SHA —— **固定策略不一致**
2. `quality-gate` job **无 `timeout-minutes`** —— 测试挂住会烧满 6 小时
3. workflow 声明 `uv 0.12.20`，本机是 `0.12.24` —— **版本漂移**（新增规则的理由）
4. 无容器层、无 release 出口 —— 结构缺口

## 7. 不做的事（明确排除）

- 不生成 GitLab CI / Jenkins / CircleCI（只留 `ir → renderer` 接缝）
- 不生成 deploy YAML，连占位都不写
- 不联网校验 action 标签
- 不在 CI 里跑 `docker push`（默认注释，需 `--allow-unverified`）
- 不自动改用户文件（`--apply` 之外零写入）

## 8. 回滚

- 插件层：`plugin_manager remove_bundle python-toolchain` → 装回 0.5.4
- 生成物：`--apply` 写过的文件旁都有 `.bak.<时间戳>`
- 仓库层：`git checkout -- .github/workflows/` 即可复原
